title: App navigation
description: Public introduction, authentication, and protected household setup.
---

Expo Router discovers routes in `apps/mobile/src/app`. The root layout installs
safe areas, the Zustand-backed appearance provider, and Tamagui once. It restores
the app session through the centralized client before selecting a route group.

| URL        | Access     | Screen                                                     |
| ---------- | ---------- | ---------------------------------------------------------- |
| `/`        | Signed out | Short introduction with create-account and sign-in actions |
| `/sign-up` | Signed out | Registration with local validation and live submission     |
| `/sign-in` | Signed out | Email/password login                                       |
| `/home`    | Signed in  | Real household list or initial household creation          |

Expo Router's `Stack.Protected` guards switch between `(auth)` and the protected `home` screen using
the Zustand session. Signing out removes authenticated screens from the history.
Unknown routes show a recovery link. The former sample overview, spending,
budgets, goals, design-system gallery, and settings routes have been removed.

The app no longer displays a navigation bar or drawers for unimplemented finance
features. Shared navigation primitives remain available in `@quilt/ui` for use
when real features need them.

See [authentication and app state](/docs/development/authentication-ui) for client
configuration, state ownership, local setup, and security boundaries.

Web exports are single-page applications. Hosting must serve `index.html` for
application paths while serving real assets normally. No deployment is configured.
